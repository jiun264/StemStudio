# StemStudio 安裝包架構

本文說明安裝包如何建置、App/Worker 如何發布、安裝器包含哪些檔案，以及安裝後的目錄與流程。執行時程序、模組責任和資料流請見 [系統架構與開發說明](ARCHITECTURE.md)。

## 1. 建置內容與順序

入口腳本是 `installer/build-installer.ps1`，安裝內容由 `installer/StemStudio.iss` 定義。建置時下載並安裝相依套件；使用者安裝時不會執行 pip。建置順序如下：

```text
CPython embeddable
  → pip
  → Demucs / PyTorch CPU / yt-dlp / imageio-ffmpeg（含 FFmpeg）
  → demucs_worker.py
  → StemStudio.App.exe
  → StemStudio.Worker.exe
  → Inno Setup 編譯成 StemStudio-Setup.exe
```

### Payload 建置步驟

1. **建立私有 CPython runtime**
   - 下載 CPython 3.12.10 x64 embeddable ZIP。
   - 解壓到 `artifacts\installer\payload\python`。
   - 修改 `python312._pth`，加入 `Lib\site-packages` 並啟用 `import site`，讓 embeddable runtime 可以載入套件。
   - 下載 `get-pip.py`，在這份私有 Python 內安裝 pip；不修改系統 Python、PATH 或 registry。
2. **安裝 Python 音訊處理依賴**
   - `backend\requirements.txt` 設定 PyTorch CPU wheel index 和 PyPI 套件來源。
   - 安裝固定版本的 Demucs、Torch CPU、torchaudio、NumPy、yt-dlp 和 imageio-ffmpeg。
   - imageio-ffmpeg wheel 提供 FFmpeg 執行檔，供 yt-dlp 將下載的音訊轉為 MP3。
   - 以私有 Python 匯入相關套件、檢查 Torch 版本，並確認 FFmpeg 執行檔存在。
3. **複製 Python worker**
   - 將 `backend\demucs_worker.py` 複製到 `payload\backend`。
   - App 會呼叫此腳本執行模型狀態檢查、準備模型、網址音訊下載與分軌。
4. **發布 WPF App**
   - 對 `StemStudio.App.csproj` 執行 `dotnet publish`。
   - 指定 `Release`、`win-x64`、self-contained 和 single-file，輸出到 `payload`。
   - App 自帶 .NET runtime，不要求使用者另外安裝 .NET。
5. **發布 .NET Worker**
   - 獨立對 `StemStudio.Worker.csproj` 執行 `dotnet publish`，同樣指定 `Release`、`win-x64`、self-contained 和 single-file。
   - 先輸出到 `worker-publish` 暫存目錄，再把自包含的 `StemStudio.Worker.exe` 複製到 `payload`。
   - 不能以一般 Build 目錄中的小型 Worker EXE 取代它：一般 Build 的 apphost 會依賴旁邊的 `StemStudio.Worker.dll` 和 .NET runtime。若從 Visual Studio 發布，發布模式必須與腳本的 self-contained、single-file、win-x64 設定相符。
6. **編譯安裝程式**
   - Inno Setup 6 使用 `installer\StemStudio.iss`，把 App、Worker、完整 `payload\python` 目錄及 Python worker 腳本壓縮成安裝程式。
   - 輸出為 `artifacts\installer\StemStudio-Setup.exe`。

## 2. Payload 與安裝器的檔案對應

Inno Setup `.iss` 的 `[Files]` 區段定義 payload 到安裝目錄的映射：

| Payload | 安裝位置 | 用途 |
| --- | --- | --- |
| `payload\StemStudio.App.exe` | `{app}\StemStudio.App.exe` | WPF 桌面應用程式 |
| `payload\StemStudio.Worker.exe` | `{app}\StemStudio.Worker.exe` | 自包含 .NET worker |
| `payload\python\*` | `{app}\python\...` | 私有 Python、套件及 imageio-ffmpeg 隨附的 FFmpeg |
| `payload\backend\demucs_worker.py` | `{app}\backend\demucs_worker.py` | Python 模型、下載及分軌 worker |

Python 目錄遞迴安裝，保留其子目錄結構。安裝目錄預設為目前使用者的 `%LOCALAPPDATA%\Programs\StemStudio`，不需要系統管理員權限。安裝器另外建立開始功能表捷徑，並提供選擇性的桌面捷徑。

模型權重不包含在安裝程式中；首次使用時 App 會先詢問使用者，再下載到可設定的模型 cache。

## 3. 建置與發布指令

建置機需要 Windows x64、.NET 8 SDK、網路連線、足夠的下載與暫存空間，以及 Inno Setup 6。從Installer資料夾底下執行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-installer.ps1
```

腳本支援以下選項：

- `-SkipRuntimeBuild`：重用現有的 `payload\python`，略過下載/重建 CPython。後續仍會安裝並驗證 `requirements.txt`，然後發布 App、Worker 和安裝程式。
- `-SkipInstallerCompile`：建置並驗證 payload，但略過 Inno Setup 編譯。
- `-InnoSetupCompiler <path>`：指定未能自動偵測到的 `ISCC.exe` 路徑。

### 更新 GitHub Release 安裝檔

安裝檔約數百 MB，請將它上傳為 GitHub Release asset，不要提交到一般 Git repository。每次正式更新使用新版本號與新 tag，避免覆寫舊版下載連結：

1. 在 `installer\StemStudio.iss` 將 `AppVersion` 更新為新版本，例如 `0.2.0`；GitHub tag 使用相同版本並加上 `v`，例如 `v0.2.0`。
2. 在 PowerShell 切換到 `installer` 資料夾並建置完整安裝檔：

   ```powershell
   Set-Location 'C:\path\to\StemStudio\installer'
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-installer.ps1
   ```

   若這台建置機已有完整的 `artifacts\installer\payload\python` runtime，可在指令最後加上 `-SkipRuntimeBuild`。輸出檔為 `..\artifacts\installer\StemStudio-Setup.exe`。
3. 確認檔案已產生並計算 SHA-256：

   ```powershell
   $installer = '..\artifacts\installer\StemStudio-Setup.exe'
   Get-Item $installer | Select-Object Name, Length, LastWriteTime
   Get-FileHash $installer -Algorithm SHA256
   ```

4. 先提交並推送來源 repository 的程式碼。接著更新 `StemStudioRelease` repository 的 `README.md`：將下載網址與 Release 頁網址改成新 tag，並將 SHA-256 換成剛計算的值；提交並推送 README。
5. 在 GitHub 開啟 `jiun264/StemStudioRelease` 的 **Releases**，選擇 **Draft a new release**。輸入新 tag（例如 `v0.2.0`）、選擇 `main` 作為 target、填寫標題與更新摘要，附加 `StemStudio-Setup.exe` 後發布。確認 Release asset 顯示的檔名和大小正確，並開啟 README 的下載連結確認可下載。

若只是修正同一版本的安裝檔，編輯該 Release，先刪除舊的 `StemStudio-Setup.exe` asset，再上傳修正版，並同步更新 Release 頁 README 的 SHA-256。替換期間舊下載連結可能暫時不可用；已公開使用一段時間的版本，優先另發新 tag。

### 只發布 App

若只修改 WPF UI，可在 Visual Studio 對 `StemStudio.App` 使用 `FolderProfile` 發布，不需要重建 Python runtime 或完整安裝程式。此專案的 FolderProfile 設定為 Release、`win-x64`、self-contained、single-file，輸出位置：

```text
src\StemStudio.App\bin\Release\net8.0-windows\publish\
```

關閉 App 後，可只用該資料夾的 `StemStudio.App.exe` 覆蓋安裝目錄中的 App EXE。保留安裝目錄原有的 Worker、`python` 和 `backend`。不要拿一般 Build 目錄中的小型 App EXE 覆蓋；它不是完整的 self-contained publish 產物。

FolderProfile 只發布 App，不會更新 Worker、Python runtime 或 `backend\demucs_worker.py`。若修改 Python worker，需另外更新安裝目錄的 `backend` 腳本；若修改 Worker 或 Python runtime，應使用完整安裝包流程，避免只替換到不完整的 Worker 或相依檔。交付完整一致版本時，以完整安裝包為準。

## 4. 模型離線封裝待辦

目前 Hugging Face 上 `adefossez/HTDemucs-6s` 模型倉庫約 55 MB，包含 `htdemucs_6s.yaml`、`5c90dfd2.safetensors` 及模型 metadata。模型倉庫提供固定 revision（目前查到 `3c5ee475be622df764938de97e4281a7b07ffa58`）；開始封裝前應重新核對 revision、檔案清單、hash 和散布授權。

預期實作步驟：

1. **先確認權利**：取得並記錄模型權重／metadata 的明確再散布許可；同時記錄 Demucs 程式、PyTorch、Python 和相依套件的 notices。未確認前不可將 checkpoint 放進公開安裝檔。
2. **固定模型輸入**：在建置腳本設定明確的模型 revision、允許的檔名和 SHA-256。只下載必要的 YAML、checkpoint 與載入所需 metadata；驗證 hash 失敗時停止建置，不產生成功樣式的 installer。
3. **放入 payload**：把原始模型資產放在例如 `artifacts\installer\payload\models\demucs\htdemucs_6s\`，並在 Inno Setup `[Files]` 將該目錄遞迴安裝到 `{app}\models\demucs\htdemucs_6s\`。模型權重是獨立資產檔，不嵌入 App EXE；安裝器壓縮後大小會增加約權重大小（另加 Python 執行環境與壓縮差異）。
4. **加入離線載入路徑**：先依目前鎖定的 Demucs 版本確認支援的本機權重載入 API，再修改 Python worker 從安裝目錄唯讀模型資產載入；若該 API 需要標準 Hub cache，明確實作將封裝資產安全複製至使用者可寫入的 cache，再啟用 Hugging Face 離線模式。不要依賴安裝目錄可寫，也不要將 symlink 當作一般檔案。
5. **定義模型狀態**：`model-status` 應分辨「內附模型完整且 hash 正確」、「使用者 cache 已就緒」及「模型缺漏／毀損」；marker 需記錄模型版本與 revision，不可僅以 marker 存在代表就緒。
6. **離線驗證**：在乾淨 Windows 測試 VM／帳號安裝，停用網路，確認模型狀態、CPU 分軌、選取音軌輸出及取消流程正常；再驗證安裝／解除安裝不刪除使用者輸出、設定或既有 cache。
7. **更新文件與發行資料**：記錄模型來源、revision、hash、授權及第三方 notices；更新 payload 大小、首次啟動 UX、安裝需求與安裝包測試清單。

授權是這項待辦的開始門檻。模型倉庫可公開下載，不代表 checkpoint 可任意重新散布；未取得明確權利時維持目前的首次下載流程。

## 5. 使用者安裝與解除安裝

1. 執行 `StemStudio-Setup.exe`，選擇安裝位置；預設為 `%LOCALAPPDATA%\Programs\StemStudio`，不需要系統管理員權限。
2. Setup 將 App、Worker、CPython 及音訊處理 runtime 安裝到同一個目錄樹，並建立捷徑；安裝期間不需下載 Python 套件或模型。
3. App 從安裝目錄定位 `StemStudio.Worker.exe`、`python\python.exe` 及 `backend\demucs_worker.py`；找不到必要檔案時會提示修復安裝，不回退呼叫全域 Python。
4. 如果模型 cache 尚無模型，App 詢問使用者是否下載；模型存入可設定的 LocalAppData cache。
5. 分軌輸出的 WAV 寫入設定中的輸出資料夾。解除安裝會刪除程式安裝目錄，但保留使用者設定、模型 cache 和輸出音訊。

正式散布前，需確認 Python、Demucs、PyTorch、yt-dlp、imageio-ffmpeg（含 FFmpeg）及其相依套件的授權與再散布條款。yt-dlp 使用 GPL-3.0-or-later；模型權重目前不內附。原約 220 MB 的安裝包估算未包含新增的 yt-dlp 和 imageio-ffmpeg，實際大小以建置產物為準。

## 6. 建置測試與可重現性限制

- Release 解決方案可建置；Python worker 有語法檢查。
- 已使用安裝包內的 private Python 和 Worker 實際檢查／下載模型、執行 Demucs，並用 CC0 吉他曲目驗證四種 stem 輸出。
- 已用 Inno Setup 編譯，並在測試目錄驗證安裝、安裝後 Worker 啟動及解除安裝。
- 已測的吉他曲目為吉他主奏，不代表完整樂團混音的串音品質；仍需評估含鼓、貝斯、人聲的混音素材。
- `requirements.txt` 固定直接依賴版本，但尚未以 hash 完整鎖定所有傳遞相依；不同日期建置可能解析到不同的間接依賴。正式發佈前應產生完整 lockfile、記錄 runtime/download hash，並完成第三方 license/notice 審查。
